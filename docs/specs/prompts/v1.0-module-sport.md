# Prompt Claude Code — App Sport & Nutrition, V1.0 (module Sport)

## Contexte

Tu développes une application Android native à usage strictement personnel (un seul utilisateur, un seul téléphone), distribuée en APK signé installé via `adb install`, sans Play Store.

L'app aura à terme deux modules : **Sport** (suivi des séances en salle) et **Nutrition** (suivi des protéines, calcul de la dose de whey, suivi créatine). **Cette itération (V1.0) ne livre que le module Sport et le socle technique**, mais l'architecture doit accueillir les lots suivants sans refonte :

- V1.1 : profil, repas (code-barres Open Food Facts, table Ciqual embarquée, favoris), jauge protéines (cible 1,6 g/kg/jour sur le dernier poids saisi), dose whey, suivi créatine
- V1.2 : synchronisation Google Drive (backup JSON + exports Markdown), API Drive v3, scope `drive.file`
- V2.x : partage des bilans vers l'app Claude, lecture Health Connect (Xiaomi Watch S4 via Mi Fitness), fréquence cardiaque en direct via le profil BLE Heart Rate standard

Contraintes fortes :
- **Hors ligne total** : la salle n'a pas forcément de réseau. Aucune fonction V1.0 ne dépend du réseau.
- **Aucune API IA, aucun service payant.** Aucune clé d'API dans le code.
- **Saisie rapide à une main** entre deux séries : gros boutons, valeurs pré-remplies, minimum de saisie clavier.
- Interface en **français**, code (identifiants, commentaires) en **anglais**.

## Stack imposée

- Kotlin, Jetpack Compose, Material 3 (thème clair + sombre, sombre par défaut)
- Architecture MVVM : `ui` / `domain` / `data`, repositories, ViewModels avec `StateFlow`
- Room (SQLite) avec migrations explicites dès la version 1 (`exportSchema = true`, schémas versionnés dans le repo)
- Hilt pour l'injection, Navigation Compose, Kotlin Coroutines/Flow
- DataStore (Preferences) pour les réglages
- `minSdk = 28` (prérequis Health Connect pour la suite), `targetSdk` = dernière version stable supportée par l'AGP utilisé
- Gradle Kotlin DSL + version catalog (`libs.versions.toml`)
- Pas de bibliothèque non maintenue ; justifie chaque dépendance ajoutée

Package : `fr.olivier.forme` (nom d'app provisoire : « Forme »).

## Modèle de données (Room)

Unités : charges en kg (`Double`, pas de 0,5 possible), durées en secondes, distances en mètres. Dates en `Instant` / `LocalDate` via TypeConverters.

**Exercise** (machine ou exercice)
- `id`, `name`, `muscleGroup` (enum : PECTORAUX, EPAULES, DOS, BRAS, ABDOS, JAMBES, CARDIO, AUTRE)
- `type` (enum) : `WEIGHTED` (charge + reps), `BODYWEIGHT` (reps, lest optionnel), `TIMED` (durée par série, option « par côté »), `CARDIO` (durée, distance, allure /500 m, calories affichées)
- `loadIncrementKg` (défaut 2,5), `settingsNote` (réglages perso : hauteur de siège, cran…), `loadNote` (ex. « chariot vide + X kg » pour le hack squat), `photoUri` (nullable)
- `archived` (Boolean) : une machine archivée disparaît des listes de choix mais conserve son historique

**WorkoutTemplate** : `id`, `name`, `code` (A, B, C, BAS…), `orderInRotation` (nullable : le modèle « bas du corps » est hors rotation), `archived` (Boolean)

Les séances réalisées (`SetEntry`, `CardioEntry`) stockent leurs propres valeurs et ne dépendent pas du contenu actuel du modèle : un modèle modifié ou archivé n'altère pas l'historique.

**TemplateExercise** : `templateId`, `exerciseId`, `position`, `targetSets`, `targetRepsMin`, `targetRepsMax`, `targetDurationSec` (pour TIMED/CARDIO), `optional` (Boolean, ex. curl biceps « si le temps le permet »), `restSec` (nullable → valeur par défaut des réglages)

**Session** : `id`, `templateId` (nullable : séance libre possible), `startedAt`, `endedAt`, `feeling` (1–5, nullable), `notes`

**SetEntry** : `id`, `sessionId`, `exerciseId`, `setIndex`, `loadKg`, `reps`, `durationSec`, `rir` (reps en réserve, nullable), `isWarmup`, `completedAt`

**CardioEntry** : `id`, `sessionId`, `exerciseId`, `durationSec`, `distanceM`, `pacePer500mSec`, `caloriesDisplayed`

**BodyWeightEntry** : `id`, `date`, `weightKg` (saisie manuelle, fréquence libre : quotidienne ou hebdomadaire)

Prévois l'extensibilité Nutrition (V1.1) sans créer ses tables maintenant.

## Écrans V1.0

1. **Accueil**
   - Séance proposée selon la rotation A → B → C (la suivante après la dernière séance de rotation terminée), bouton « Démarrer »
   - Accès rapide aux autres modèles (dont « Bas du corps ») et à une séance libre
   - Dernières séances (date, modèle, durée)
   - Carte poids : dernière pesée, moyenne mobile 7 jours, bouton « + pesée »

2. **Séance en cours**
   - Liste ordonnée des exercices du modèle ; possibilité d'ajouter un exercice du catalogue, de sauter un exercice optionnel, de réordonner
   - Pour chaque exercice : séries pré-remplies avec les valeurs de la dernière fois (charge, reps) ; boutons +/- (incrément de la machine pour la charge, 1 pour les reps) ; bouton « Valider la série »
   - Champ RIR optionnel par série (0 à 5, sélection par puces)
   - Timer de repos démarré automatiquement à la validation : notification + vibration en fin de repos, visible écran verrouillé (foreground service ou notification avec chronomètre)
   - Cardio (rameur) : saisie durée, distance, allure, calories
   - Fin de séance : ressenti 1–5, notes, récapitulatif (volume total, volume par groupe musculaire, comparaison avec la séance précédente du même modèle, records battus)
   - La séance en cours survit à la mise en arrière-plan et au kill du process (état persistant en base, reprise au lancement)

3. **Historique**
   - Liste des séances, détail d'une séance
   - Par exercice : historique des séries, meilleure charge, meilleur volume, graphique de charge max par séance (Compose Canvas ou bibliothèque légère justifiée)

4. **Configuration**
   - **Catalogue des exercices** : ajout, modification, archivage/désarchivage, photo optionnelle (sélecteur photo système, pas de permission caméra en V1.0)
   - **Modèles de séance** (appelés à évoluer souvent) : création, duplication (partir d'une séance existante pour en faire une variante), modification (nom, exercices, ordre par glisser-déposer, séries/reps/durée cibles, repos, exercice optionnel), archivage/désarchivage, gestion de la rotation (quels modèles en font partie et dans quel ordre)
   - Modifier ou archiver un modèle ne modifie **jamais** les séances passées : l'historique reste lisible tel qu'il a été réalisé
   - **Réglages** : repos par défaut (90 s), thème, unités
   - **Sauvegarde** : export / import d'un fichier JSON complet via le Storage Access Framework (avec numéro de version du schéma). Indispensable avant la synchro Drive de la V1.2

5. **Poids** : saisie manuelle, liste, courbe avec moyenne mobile 7 jours

## Règles métier

- **Suggestion de progression** (règle du programme) : pour un exercice `WEIGHTED`, si la dernière série de la séance précédente a été validée avec un RIR ≥ 3, l'app propose charge + `loadIncrementKg` à la séance suivante (badge « ↑ suggéré », jamais appliqué sans validation). Sans RIR saisi : si toutes les séries ont atteint `targetRepsMax`, même suggestion.
- **Exercices `BODYWEIGHT` / abdos** : la progression suggérée porte sur les reps (allonger les séries avant de charger).
- **Records** : meilleure charge (à reps ≥ targetRepsMin) et meilleur volume (charge × reps cumulés) par exercice ; signalés en fin de séance.
- **Rotation** : seuls les modèles non archivés avec `orderInRotation` participent ; « Bas du corps » ne décale pas la rotation. Ajouter, retirer ou réordonner un modèle dans la rotation depuis la Configuration recalcule la séance proposée.
- **Bilan texte** : générer en fin de séance un résumé texte brut (date, modèle, exercices, séries, volume, comparaison) copiable dans le presse-papiers. Ce format servira en V2 au partage vers Claude et à l'export Markdown.
